## Buckets
- "directories" to store "files"(objects)
- globally unique name
- defined at REGION level
- Naming convention
    - No uppercase, no underscores
    - 3-63 characters long
    - Not an IP
    - must start with lowercase letter or a number
    - must NOT start with prefix xn-- or end with suffic -s3alias

## Objects
All objects have a Key (path)
- s3://{bucket}/{pre/fix/}{object}
eg: s3://my-bucket/my_folder/my_subfolder/my_file.txt
- max object size: 5TB
- > 5GB files must use "multi-part upload"
- can have upto 10 tags (unicode key-val pairs)
- supports versioning

## Security
User-Based
- IAM policies - which API calls should be allowed for a specific IAM user

Resource-Based
- Bucket policies - bucket wide rules from the S3 console - allows cross account
- Object ACL - finer grained (can be disabled)
- Bucket ACL - less common

* an IAM principal can access an S3 object if
- the user IAM permissions ALLOW it OR the resource policy ALLOWS it
- AND there is no explicit DENY

Objects can be encrypted

## Versioning
- enabled at bucket-level
- overwriting a key will bump up the version of the object
- protect against unintended delete
- ability to rollback
- any file that is not versioned prior to enabling versioning will have 'null' version
- suspending versioning does not delete previous versions

## Replication
Cross-Region Replication (CRR)
* compliance, lower latency access, replication across accounts
Same-Region Replication (SRR)
* log aggregation, live replication across production & test accounts
must enable versioning
buckets can be in different AWS accounts
copying is async
should have proper IAM Permissions
Notes:
- after enabling replication, only NEW objects are replicated
- you can replicate existing objects (or those that failed replication ) using S3 Batch Replication

For DELETE operations
- can replicate delete markers (optional setting)
- deletions with a version ID are not replication

There is no "chaining" of replication


## Storage Classes
S3 Standard
- Frequent Access (FA)
- 99.99 % Availability
- frequent access
- low-latency, high-throughput
- sustain 2 concurrent facility failures
- use cases: Big Data Analytics, mobile and gaming apps, content distribution

S3 Standard-IA
- Infrequent Access (IA)
- 99.99% Availability
- less frequently accessed but requires immediate access
- lower cost than S3 Standard
- Use cases: Disaster Recovery, backups

S3 One Zone-IA
- 99.5 % Availability
- usecases: storing seconday beackup of on-premise data, or data that can be created


S3 Glacier Storage Classes
- low-cost meant for archiving/backup
- price for storage + object retrieval cost

S3 Glacier Instant Retrieval
- millisecond retrieval, great for data accessed once a quarter
- min storage duration of 90 days

S3 Glacier Flexible Retrieval
- expedited (1-5 min), standard (3-5 hours), bulk(5-12 hrs) - free
- min storage duration 90 days

S3 Glacier Deep Archive
- standard (12 hours), bulk (48 hours)
- min storage duration of 180 days

S3 Intelligent-Tiering
- small monthly charges for monitoring
- moves objects automatically between Access Tiers based on usage
- there are no retrieval charges

Access Tiers
- Frequent Access tier (automatic) default tier
- Infrequent Access tier (automatic) objects not accessed for 30 days
- Archive Instant Access tier (automatic) objects not accessed for 90 days
- Archive Access tier (optional) configurable from 90 days to 700+ days
- Deep Archive Access tier (optional) config from 180 days to 700+ days 

## Requester Pays
- in general, bucket owner pays for both storage cost as well as data transfer cost
- with Requester Pays buckets, the requester pays the cost of the request and the data transfer/download
- requester must be authenticated in AWS

## Event Notifications
- Event -> S3:ObjectCreated, S3:ObjectRemoved etc
- supports Object name filters (eg: only *.jpg)
- eg: generate a thumbnail when an image is uploaded 
- takes few seconds to a minute to deliver events
- events can be delivered to SNS, SQS, Lambda
- IAM Permissions required for S3 to deliver events to SNS, SQS, Lambda
- All S3 Events are delivered to Amazon EventBridge

## Baseline performance
- 100-200ms latency
- 3500 PUT/COPY/POST/DELETE and 5500 GET/HEAD requests per second per prefix
- prefix-es are unlimited
- eg: bucker/foo/bar/file_one -> prefix=/foo/bar
- ie. If you spread your reads across 4 prefixes, you can effectively achieve 22000 read requests per second

## Performance
Multi-Part upload
- divide large file into parts; parallel uploads
- recommended for files > 100 MB
- must use for files > 5 GB

S3 Transfer Acceleration
- files are first transferred to an AWS Edge location
- and then forwarded to destination S3 bucket via private links
- compatible with Multi-part upload

S3 Byte-Range Fetches
- Parallely get specific byte ranges
- better resilience to failures
- speed up downloads
- used to retrieve partial data (head of file)

## Batch Operations
perform bulk operations on S3 objects with a single request
- modify object metadata and properties
- copy objects across buckets
- encrypt un-encrypted objects
- modify ACL tags
- restore objects from Glacier
- invoke lambda function to perform a custom operation on each object
 A Batch 'job' consists of a list of objects, the action and optional parameters
Batch Operations manages retries, tracks progress and sends completion notifications and reports
- you can use S3 Inventory --> Athena to query and filter objects

## Security
### Encryption-At-Rest
#### Server-Side:
- S3-managed Keys (SSE-S3)
    - AWS managed key
    - enabled by default
    - "x-amz-server-side-envryption":"AES256"
    
- KMS-managed Keys (SSE-KMS)
    - user controlled Keys 
    - can be audited via CloudTrail
    - "x-amz-server-side-encryption":"aws:kms"
    - "Read" requires access to Object + access to KMS
    **Limitation**: 
        - KMS API quotas-per-second are applicable. 5500/10_000/30_000 req/s based on region
    - can request a quota increase using Service Quotas console

- Customer-provided Keys (SSE-C)
    - keys managed by customer externally
    - encryption key is not stored by AWS
    - HTTPS Request + Key in header

#### Client-Side
- use client-side libraries (Amazon S3 Client-Side Encryption Library)
- clients encrypt-decrypt externally

### Encryption-In-Flight
- SSL/TLS => HTTPS
- HTTPS is recomennded
- HTTPS is mandatory for SSE-C
- a `BucketPolicy` can force Encryption-in-transit using aws:SecureTransport (set to True when using HTTPS)

### CORS
Cross-Origin Resource Sharing (CORS), is a web-browser based mechanism to allow requests to other origins while visiting the main origin
- Origin -> scheme + host (domain) + port
- eg: http://example.com/app1 & http://example.com/app2 are same Origin whereas http://www.example.com and http.other.example.com are different Origins.
- A request will not be fulfilled in this case unless the other origin allows for the requests using Access-Control-Allow-Origin CORS Headers.
- For S3 buckets with Static Website enabled, if a client makes a cross-origin request, the buckets needs to enable the correct CORS headers.
- Access-Control-Allow-Origin: http://my-origin-bucket-s3-website.us-west-2.amazonaws.com

### MFA Delete
force users to require MFA for carrying out important actions on S3.
To use MFA Delete, Versioning must be enabled
Only the bucket owner (root account) can enable/disable MFA Delete 

required for:
- permanently delete an object version
- suspend versioning

not required for:
- enabling versioning
- list deleted versions

### Access Logs
- audits ALL S3 requests
- from ALL AWS accounts
- writes logs to a 'target' S3 bucket 
- 'target' S3 bucket should be in same AWS region
- WARNING: "Logging" loop; if 'target' bucket is same as 'monitored' bucket

### Pre-Signed URL
uses security credentials to give a time-limited permission to download objects
URL Expiry
- console -> 1min to 720 mins
- AWS CLI -> --expires-in -> default 3600 sec, max 604800 168 hrs

- use cases:
    - allow only logged-in users to downloads premium videos from S3 
    - allow ever-changing list of users to download files by generating URLs dynmaically
    - allow temp user to uload file to a precise location

### Glacier Vault Lock
- Write Once Read Many (WORM) model
- create a `Vault Lock Policy`
- lock the policy itself for future edits
- Usecase: Date Retention Compliance

### S3 Object Lock
adopt WORM model at object level
block an object version from being deleted for a specified amount of time

NOTE: versioning must be enabled on the Bucket
- Retention Period 
    - protect the object for a fixed period of time
    - can be extended
- Legal Hold:
    - protect the object indefinitely
    - independant from retention period
    - needs s3:PutObjectLegalHold IAM permission

- Compliance mode:
    - object versions cannot be overwritten or deleted by ANY user (including root)
    - retention mode cannot be changed and retention period cannot be shortened.
- Governance:
    - most users cannot overwrite or delete an object version or alter its lock settings
    - select users are given permissions to change retention or delete objects

### Access Points
simplify security management for S3 Buckets at scale
- has its own DNS name 
    - Internet Origin
    - VPC Origin:
        - accessible only from within VPC
        - must create a VPC Endpoint (Gateway or Interface Endpoint) to access the Access Point
        - VPC Endpoint Policy must allow access to the target Bucket and Access Point
- has an Access Point Policy (similar to Bucket policy) to manage access permissions

### S3 Object Lambda
use Lambda to change objects before it is retrieved by caller application
- A single S3 bucket can have an S3 Access Point and S3 Object Lambda Access Point on top of it which supports multiple use cases
- UseCases:
    - Redacting PII information from objects
    - coversion across data formats like XML to JSON etc
    - Resizing and Watermarking images on the fly using caller-specific details
